# VC ERP · LP 출자기관 업무 관리

> 여러 운용사(GP)의 여러 조합에 대한 출자를 계획·심사부터 납입·사후관리·성과 분석·청산까지 관리하는 출자기관(LP)용 ERP MVP입니다.

**LP의 결정(심사·결재), 거래 확인(대사), 전체 현황 파악(성과 분석)을 연결하고, GP와 주고받는 업무까지 이어지게 만들었습니다.**

[LP 데모](https://vc-erp-lp.vercel.app) · [서비스 소개](https://vc-erp-lp.vercel.app/intro) · [GP 저장소](https://github.com/choby-pm/vc-erp-gp) · [기획 문서](docs/README.md)

개인 연구·포트폴리오 프로젝트입니다. 기관·조합·금액은 가상 데이터이며 실제 금융 서비스와 무관합니다.

## 1. 해결하려는 문제

LP는 여러 GP의 조합을 심사하고, 납입 요청을 받아 송금하며, 보고서와 분배 내역을 모아 성과를 확인합니다. 이때 **GP가 요청한 내용, 내부에서 승인한 내용, 실제로 돈이 움직인 사실**은 서로 다른 기록입니다.

이 프로젝트는 각 기록의 책임과 상태를 구분하면서, 출자 건 하나의 전 과정과 기관 전체 포트폴리오를 함께 볼 수 있도록 설계했습니다.

| 사용자 | 필요한 일 | 서비스의 대응 |
|---|---|---|
| 출자 담당자 | 제안 심사, 결재 요청, 납입·수령 기록, 사후관리 | 출자 건별 이력과 업무별 목록, 확인할 일·일정 |
| 결재권자 | 조건과 근거를 확인하고 승인·반려 | 선정·납입·총회 투표 결재, 자기 기안 승인 차단 |
| 기관 관리자 | 사용자·평가 기준·GP 연결 관리 | 기관 설정, 역할 권한, 연동 상태와 감사 로그 |
| 조회 사용자 | 기관의 출자·성과 현황 파악 | 쓰기 권한 없이 정보 조회 |

## 2. 핵심 업무 흐름과 MVP 범위

| 단계 | 주요 기능 | 다음 업무로 이어지는 결과 |
|---|---|---|
| 계획 | 출자 예산, 분야별 배분, 출자사업 공고·모집 부문 | 심사·선정에 사용할 예산과 기준 마련 |
| 심사·선정 | 제안 접수, 심사 단계·가중 평가표, 선정 조건·결재 | 예산·부문 한도 안에서 선정하고 GP에 결과 전달 |
| 약정·결성 확인 | 출자 건 생성, 선정 조건·결성 체크리스트 | 약정과 실제 조합 결성 상태 확인 |
| 납입 | 캐피탈콜 수신, 납입 결재, 송금 기록, 자금 계획 | 실제 납입 기록과 GP 원장 대사 |
| 사후관리 | 통지 확인, GP 보고 검토, 투자 의무 근거, 자료 요청, 총회 투표 | 확인·검토·의사결정 이력 보존 및 GP 전달 |
| 회수·성과 분석 | 분배 수령·대사, 기준일 성과, 포트폴리오 분석 | 출자 건별·기관 전체 성과 파악 |
| 청산 | 청산 조건표, 최종 성과 확정·잠금 | 완료 시점의 성과와 근거 보존 |

연동 GP와 수기로 관리하는 외부 GP 출자를 함께 다룹니다. 성과는 DPI·RVPI·TVPI·XIRR과 빈티지·분야·운용사별 구성을 제공합니다.

## 3. 주요 기획 결정

| 업무에서 생기는 질문 | 정한 정책 | 의도 |
|---|---|---|
| 납입 승인이 나면 송금 완료인가? | 결재 승인과 실제 송금 기록을 분리 | 내부 의사결정과 자금 이동 사실을 구분 |
| 송금했는데 GP 입금 기록이 없으면? | LP 장부와 GP 원장 사본을 따로 보관하고 대사. 확인 대기 기간 적용 | 시차와 실제 금액 불일치를 구분 |
| 승인 전에 조건이 바뀌면? | 기안 시점 조건을 보존하고 승인 직전 규칙을 재검사 | 예산·한도·지급 조건 변경에 따른 잘못된 승인 방지 |
| 다른 기관이 같은 조합에 출자하면? | 기관별 데이터와 권한을 분리 | 같은 조합이어도 각 기관의 출자·결재 정보 보호 |
| 상세 성과와 전체 성과가 다르면? | 같은 기준일을 적용하고 숫자 일치 점검 제공 | 비교 가능한 지표와 추적 가능한 계산 근거 제공 |
| 자료 요청을 전송하면 업무가 끝나는가? | 전송 상태와 접수·회신·수신 확인 상태를 분리 | 전달 성공과 담당자의 업무 완료를 구분 |
| 선정이나 캐피탈콜이 취소되면? | 상대에게 통보하고 확인하는 절차 제공 | 양쪽 기록을 임의로 덮어쓰지 않고 변경 사실 추적 |

상세 정책은 [업무 규칙](docs/04_business_rules.md), 선택 이유는 [결정 기록](docs/99_decisions.md)에 남겼습니다.

## 4. GP와 연결되는 사용자 경험

| LP의 업무 | GP와 연결되는 결과 |
|---|---|
| 공고 게시·제안 접수·선정 결재 | GP의 공고 지원 접수, 선정 응답과 앵커 조건 전달 |
| 납입 결재·송금 기록 | GP의 입금 확인 기록과 비교해 대사 |
| 통지 확인·보고 검토 | 통지 받음 확인을 GP에 전달, 공개 범위 내 보고 조회 |
| 총회 안건 검토·투표 결재 | GP 총회에 ‘LP 직접’ 투표 반영 |
| 자료 요청·회신 수신 | GP의 요청 접수·보고 회신과 양쪽 수신 완료 상태 연결 |
| 분배 수령 기록 | GP 지급 기록과 대사 |

웹훅은 변경을 알리는 신호로 사용하고, GP API를 다시 조회해 데이터를 반영합니다. 전송 실패 시 재시도하며, 담당자는 연동 상태와 업무 처리 상태를 구분해 확인할 수 있습니다.

## 5. 데모에서 확인할 흐름

[LP 데모](https://vc-erp-lp.vercel.app) 첫 화면의 **데모로 둘러보기**에서 기관과 역할을 선택합니다. 데모 DB는 매일 03:00 KST에 초기화됩니다.

1. **하늘연금 · 출자 담당**: 대시보드에서 예산·포트폴리오·납입 예정·주의 목록을 확인합니다.
2. **출자 심사 → 결재함**: 제안의 선정 조건을 확인하고 기안한 뒤, 결재권자로 로그인해 승인합니다. 연결된 GP에서 ‘확약 · LP 직접’을 확인합니다.
3. **납입·분배 → 캐피탈콜**: 납입 기안 → 결재 승인 → 송금 기록 순서로 처리합니다. GP가 입금을 기록하면 출자 건 상세에서 대사 결과를 확인합니다.
4. **포트폴리오 → 성과**: 기준일을 바꾸고 출자 건별 현금흐름과 전체 성과를 비교합니다.
5. **바다성장출자로 로그인**: 하늘연금의 출자·결재 데이터가 보이지 않는지 확인합니다.

총회 투표·분배 수령·청산까지 포함한 상세 경로는 [데모 가이드](docs/00_summary.md)와 [시연 대본](docs/97_demo_script.md)에 있습니다.

## 6. 기획 과정과 검증

VC 관리·운용 경험자 인터뷰와 공개 사용자 가이드를 바탕으로 LP의 역할·업무 흐름·필요 기능을 정리했습니다. AI(Claude Code·Codex)를 활용해 기획 문서와 서비스를 구현하고, 사용자 정책 선택을 결정 기록에 남겼습니다. 인터뷰는 초기 도메인 조사이며 실제 규약·금융 산식의 현업 검증을 대신하지 않습니다.

- **기록된 검증 결과**: 2026-10-17 배포 후 API 시나리오 QA에서 LP·연동 45/45, GP 41/41 통과. [검증 기록](docs/106_validation_handoff.md)
- **화면 검증**: 로컬 실제 브라우저에서 선정→GP 확약, 납입→대사 일치, 기준일별 상세·전체 성과 일치 확인. [통합 QA 보고](docs/qa-reports/2026-10-17-w08.md)
- **숫자 검증**: 같은 검수 시점의 개발 DB에서 숫자 일치 점검 84개 통과. 점검 건수는 데이터에 따라 달라집니다.
- **성과 해석**: 업무와 데이터의 연결을 확인한 MVP입니다. 실제 고객 도입, 업무 시간 절감, 투자 성과 개선은 측정하지 않았습니다.

### 현재 한계

평가액 롤포워드와 일부 금융·회계 정책은 단순화한 가정입니다. 실제 규약과 계산 예시를 통한 정책 검증이 필요합니다. 배포본 브라우저 재검증, 실제 파일 다운로드, 일부 장애·시간 경과 재시도 검증도 남아 있습니다. API QA는 화면 검증을 대신하지 않습니다.

## 8. 기술 구성과 로컬 실행

Next.js 16 · TypeScript · Tailwind CSS · PostgreSQL(Neon) · Vercel을 사용합니다. GP와 별도 앱·DB로 구성하고 인증 API와 서명 웹훅으로 연결합니다.

GP 마이그레이션과 서버를 먼저 준비합니다. LP 저장소 루트에서 `docs/env.example`을 `.env.local`로 복사하고 개발용 DB와 GP 연결값을 설정합니다. 비밀값은 커밋하지 않습니다.

```bash
npm install
npm run db:migrate
npm run db:seed
# GP의 npm run db:seed-lp-demo 출력 ID로 기관 a·b를 각각 연결
npm run gp:link -- --org a --gp-lp-id <GP_출자자_ID>
npm run gp:link -- --org b --gp-lp-id <GP_출자자_ID>
npm run db:seed-scenario
npm run dev
```

기본 주소는 `http://localhost:3200`입니다. `GP_DEMO_BASE_URL`은 `/api/lp/v1`까지 포함해야 합니다. 연결별 웹훅 설정과 실행 조건은 [실행·연동 안내](docs/106_validation_handoff.md)를 참고하세요. 숫자 일치 점검은 `npm run check:numbers`로 실행합니다.
