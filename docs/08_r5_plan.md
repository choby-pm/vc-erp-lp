## 1. R5에서 보여줄 것

R5가 끝나면 **출자한 뒤 GP가 보내는 것**을 LP가 빠짐없이 받아 처리하고, 처리할 일이 한 화면에 모인다.

```
GP: 통지 발송        ──웹훅──→ LP: 통지함 (확인하면 ──API──→ GP에 "확인함")
GP: 정기 보고 발행   ──웹훅──→ LP: 보고 수집 (스냅샷·우리 몫 평가액·PDF) → 검토 완료 → 조건 준수 점검(주목적 투자 비율)
GP: 총회 소집        ──웹훅──→ LP: 안건 수신 → 안건별 검토 의견·찬반 → 투표 결재 → 승인되면 ──API──→ GP에 직접 투표
GP: 총회 결과 확정   ──웹훅──→ LP: 안건 결과(가결·부결)
LP: 대시보드 주의 목록 — 결재 대기, 납입 기한 임박·경과, 대사 불일치 7일 경과, 결성 기한, 보고 미제출·미검토, 점검 미달, 투표할 총회, 못 보낸 것 …
```

- 수기 조합(한결)도 통지·보고·총회를 직접 입력해 같은 흐름 (GP 전달 대신 "서면 제출 완료" 기록)
- 결재를 거는 세 번째 곳(투표)이 생긴다 → 출자 선정·납입·투표 (01 3장)

## 3. 단계별 계획 (5단계, 순서대로)

각 단계가 끝날 때마다 검수 요청을 드린다.

### R5-1. 통지함

| 할 일 | 내용 |
|---|---|
| 연동 수신 | `notice.sent` 웹훅(모든 종류) → GP 통지 목록을 다시 읽어 우리 통지함에 만들기·갱신 (출자 제안·캐피탈콜 통지도 통지함에 남긴다. 기존 처리는 그대로) |
| 확인 | 출자 담당이 확인 → `acknowledged_at`. 연동이면 저장 뒤 GP에 확인 전달, 못 보내면 `gp_ack_sent_at` 이 비어 있고 주기 작업·"못 보낸 것 지금 보내기"가 다시 보냄 (BR-NTC-02, BR-SYNC-11) |
| 수기 통지 | 우편·메일로 받은 통지 기록 (BR-NTC-01) |
| 화면 | `/notices` 통지함 (미확인 / 전체, 종류별), 조합 화면에 그 조합 통지 |

> R5-1 구현 (2026-10-03): `lib/services/notices.ts` (목록·수기·확인·GP 전달·못 보낸 것·syncNotices), 통지 웹훅 처리(모든 종류), 첫 맞추기에 통지, 주기 작업·"못 보낸 것 지금 보내기"에 통지 확인, `/notices` 화면, 조합 화면 최근 통지, GP 연동 화면에 못 보낸 확인. DB 변경 없음
> 검수: 두 기관 GP 통지 8건씩(모두 조합에 이어짐, 다시 해도 늘지 않음), 확인 → GP 확인 시각 기록, 다시 확인해도 처음 시각, 결재권자·다른 기관 차단, 연동 조합 수기 통지 차단, 한결 수기 통지(GP 전달 없음), GP 꺼짐 → 못 보냄 → 켜고 지금 보내기 → 전달. 검수 데이터는 되돌림(모두 미확인). 통지 웹훅으로 새 통지가 들어오는 것은 R5-5 배포에서 확인

### R5-2. 보고 수집 · 검토 · 조건 준수 점검

| 할 일 | 내용 |
|---|---|
| 연동 수신 | 보고 통지 → GP 보고 목록을 다시 읽어 저장 (스냅샷 그대로, 우리 몫 평가액, 정정 보고면 같은 기간 이전 보고 `superseded_at`) (BR-RPT-01·05) |
| 수기 보고 | 기간·받은 날·우리 몫 평가액·주목적 투자 비율 입력. 같은 기간이면 정정 보고로만 (BR-RPT-02·05) |
| 검토 완료 | 출자 담당이 읽고 표시 (BR-RPT-04) |
| 조건 준수 점검 (L34) | 필요 비율(조합 규약의 주목적 의무 비율) vs 실제 비율(보고 숫자). 연동 보고는 받을 때 자동 기록, 수기는 담당자가 비율 입력. 투자 기간 중 미달은 "참고", 투자 기간 끝난 뒤 보고의 미달만 주의 목록 (BR-CHK-01) |
| 보고서 PDF (L36) | 연동 GP 보고서 PDF는 볼 때 GP에서 받아 흘려보낸다. 수기 보고 PDF 올리기는 고도화 |
| 화면 | `/reports` 보고 목록(미검토 우선), 보고 상세(스냅샷: 투자·평가·현금·성과 숫자, 점검 결과), 조합 화면에 보고·평가액 |

> R5-2 구현 (2026-10-03): `lib/services/reports.ts` (연동 받기·수기·검토·점검, 판정 `checkView`), GP 클라이언트 파일 내려받기(`download`), 보고 통지 처리·조합 맞추기에 보고, `/reports`·`/reports/[id]` 화면, 조합 화면 보고 목록·수기 입력. DB 변경 없음
> GP 시드에 2026년 2분기 보고 발행 추가 (L38 앞당김). ⚠️ 시드 스크립트는 GP 서버 밖에서 돌아 웹훅이 바로 나가지 않는다 → LP "지금 가져오기"(또는 주기 작업)로 받는다
> 검수: 2분기 보고 수신(두 기관, 평가액 하늘 23.75억·바다 19억), 자동 점검 30%/60% → "참고(투자 기간 중)", 다시 점검도 GP 값, 투자 기간 뒤 미달 → "미달"(판정 함수), 검토 완료(처음 시각 유지), 수기 보고(연동 조합 차단·날짜·중복→정정·이전 보고 대체·수기 점검), 권한·다른 기관 차단. 검수 데이터는 되돌림 (GP 보고·자동 점검은 시연용으로 둠)

### R5-3. 총회 · 투표 결재 · GP에 직접 투표

| 할 일 | 내용 |
|---|---|
| 연동 수신 | 총회 통지·`meeting.result_finalized` → GP 총회 목록을 다시 읽어 총회·안건·결과·`voting_open` 맞추기 |
| 투표안 | 안건별 찬반 + 내부 검토 의견 (검토 의견은 GP에 보내지 않음, BR-VOTE-03). 결재 대기 중에는 못 바꿈 (BR-APR-03) |
| 투표 결재 | 모든 안건에 찬반이 있어야 기안 (BR-VOTE-02). 결재는 총회 단위, 스냅샷에 안건·찬반·검토 의견 |
| 제출 | 승인되면 저장 뒤 GP `PUT …/votes` 로 한 번에 (BR-VOTE-04). 못 보내면 다시 보냄. GP가 마감 뒤라 거부하면 주의 목록 "투표 제출 실패" (BR-VOTE-06). 다시 투표는 새 결재 (BR-VOTE-05) |
| 수기 총회 | 총회·안건 입력 → 같은 결재 → "서면 제출 완료" 기록 |
| 화면 | `/meetings` (투표할 것 우선), 총회 상세(안건·검토 의견·찬반·결재·제출·결과), 결재함에 투표 결재 |

> R5-3 구현 (2026-10-03): 마이그레이션 008(`agendas.description`, `meetings.vote_submit_*`). `lib/services/meetings.ts` (투표안·결재·제출·다시 보내기·수기 총회·결과·GP 받기), 결재 승인 → GP 제출, `meeting.result_finalized`·총회 통지 처리, 주기 작업·"못 보낸 것"에 투표, `/meetings`·총회 상세·결재함 투표 화면, 조합 화면 총회. GP 시드에 정기총회 소집(10/30, 안건 2개) 추가 (L38)
> 검수: 정기총회 수신(두 기관), 결성총회 GP 기록 투표 받아 둠, 찬반 다 안 정하면 기안 불가, 결재 대기 중 수정 불가, 권한·다른 기관 차단, 승인 → GP "LP 직접"(찬성·반대), 제출 뒤 찬반 변경 → 새 결재 없이 제출 불가 → 재결재 승인 → GP 값 바뀜, GP 개최 처리 → 결과·투표 마감 반영(웹훅), 마감 뒤 승인 → GP 거부 → "제출 실패"(다시 보내지 않음), 수기 총회(결재 → 서면 제출 → 결과 기록). 검수 데이터는 GP·LP 모두 되돌림

## 4. 정할 것

### Q1. 조건 준수 점검을 언제·어떻게 판정할까?

GP 보고의 주목적 투자 비율은 "지금까지 주목적에 투자한 금액 ÷ 약정 총액"이다. 의무 비율(예: 60%)은 보통 **투자 기간이 끝날 때** 채우면 되므로, 투자 기간 중에는 미달이 정상이다.

| 선택지 | 내용 |
|---|---|
| **A (추천)** | 연동 보고는 **받을 때 자동으로 점검** 기록(비율은 GP 값), 수기는 담당자가 비율을 넣어 기록. 투자 기간 중 미달은 **"참고(투자 기간 중)"**로만 보이고, 투자 기간이 끝난 뒤 보고에서 미달일 때만 주의 목록 |
| B | 04 그대로: 미달이면 언제든 `fail` → 주의 목록 (투자 초기 조합은 늘 경고가 뜬다) |

### Q2. 보고 기한(분기 말 + 45일, L11)을 어느 분기부터 따질까?

| 선택지 | 내용 |
|---|---|
| **A (추천)** | 출자 건이 활성이 된 날(결성 확인일. 가져온 출자 건은 연결한 날)이 속한 **분기부터**. 연결 전 과거 분기는 따지지 않는다 (이 시스템을 쓰기 전 일) |
| B | 조합 결성일부터 모든 분기 (가져온 출자 건은 과거 분기가 모두 "미제출"로 뜬다) |

### Q3. 수기 보고의 PDF 첨부

| 선택지 | 내용 |
