## 1. R6에서 보여줄 것

R6가 끝나면 **돈이 돌아오는 흐름**과 **얼마나 벌었는지**가 이어진다.

```
GP: 분배 확정(통지)   ──웹훅──→ LP: 분배 수신 (회차·금액·원금 반환/수익 구분) → "수령 대기"
GP: 분배 지급         ──웹훅──→ LP: GP 원장 사본 '분배' (GP는 보냈다)
LP: 수령 기록         ──────→ 우리 장부 '분배' 행 + 분배 대사 → "일치"
LP: 성과 지표         ──────→ 출자 건별·전체 TVPI · DPI · RVPI · IRR (우리 장부 기준, 기준일 선택)
LP: 포트폴리오 분석   ──────→ 빈티지·분야·운용사·연동/수기별로 모아 보기
LP: 청산 확인         ──────→ 조건 점검 → 최종 성과 고정 → 출자 건 잠금
```

- 가져온 출자 건의 과거 분배(GP 원장에 있고 우리 장부에 없음)도 "가져온 수령"으로 옮겨 분배 대사가 맞는다 (L27에서 R6로 미룬 것)
- 주의 목록에 "수령 대기 분배"가 생긴다 (R5-4에서 미룬 것)

## 3. 단계별 계획 (5단계, 순서대로)

각 단계가 끝날 때마다 검수 요청을 드린다.

### R6-1. 분배 수신 · 수령 기록 · 분배 대사

| 할 일 | 내용 |
|---|---|
| 연동 수신 | 분배 통지·조합 맞추기 → GP 분배 목록을 회차로 만들기·갱신 (금액 = 내 몫, 원금 반환 = 원금 반환 단계, 수익 = 나머지 단계 합, 단계별 금액 그대로). GP가 취소하면 `cancelled` (BR-DIST-01·04) |
| 수령 기록 | 수령일(분배일 이후·미래 불가) → 한 트랜잭션: 수령 + 우리 장부 '분배' 행 + (연동) 분배 대사. 결재 없음 (BR-DIST-03). 연동 분배도 담당자가 통장 입금을 보고 기록한다 (L39). GP가 지급했는데 기록 전이면 "GP 지급됨 · 수령 기록 전" |
| 정정 · 취소 | 입력 실수 정정은 원래 날짜 취소 행 (BR-DIST-05). GP가 지급 뒤 취소하면 오늘 날짜 취소 행 (BR-DIST-04) |
| 수기 분배 | 회차 유일, 원금 반환 + 수익 = 금액 (BR-DIST-02) |
| 가져온 수령 | 가져온 출자 건의 연결 전 GP 분배 원장 행 → 결재·입력 없이 "가져온 수령" (L27·L32와 같은 방식) |
| 대사 | 동기화 때 분배도 대사 (지금은 약정·납입만) |
| 화면 · 주의 | `/distributions` (수령 대기 / 전체), 출자 건 상세에 분배 표, 주의 목록 "수령 대기 분배" |

> R6-1 구현 (2026-10-03): 마이그레이션 010(`distributions.gp_status`·`received_via`). `lib/services/distributions.ts` (GP 받기·가져온 수령·GP 취소 반영·수령·정정·수기), 분배 통지 처리·조합 맞추기에 분배, 동기화 분배 대사, `/distributions` 화면, 출자 건 상세 분배 표·수기 입력, 주의 목록 "수령 대기 분배". GP 시드에 2차 분배 확정(L43)
> 검수: 1차 분배 → 가져온 수령(하늘 10억·바다 8억, 분배 대사 일치), 2차 → 수령 대기(6.98억·4.65억, 전부 원금 반환 — 아직 원금을 다 돌려받지 못해 워터폴상 수익 없음), 수령일 검사(분배일 전·미래), 권한·다른 기관, 가져온 수령 정정 차단, 수기 분배(원금 5억+수익 1억, 회차 중복·연동 조합·0원 차단) → 수령 → 다시 수령 차단 → 정정(원래 날짜 취소 행), 연동 수령 → 분배 대사 불일치(확인 대기), GP 취소 → 오늘 날짜 취소 행 → 대사 일치. 검수 데이터는 되돌림. GP 지급 → 대사 일치는 R6-5 배포에서

## 4. 정할 것

### Q1. 연동 분배를 언제 "수령"으로 볼까?

GP가 "지급"을 기록해도 실제로 우리 통장에 들어왔는지는 우리가 확인해야 한다. 납입(R4)은 우리가 보낸 것을 기록하고 GP 입금 기록과 대사했다.

| 선택지 | 내용 |
|---|---|
| **A (추천)** | 납입과 같은 방식: **담당자가 통장 입금을 보고 수령을 기록**한다. GP가 지급했는데 우리가 아직 기록하지 않았으면 분배 대사가 불일치(확인 대기 7일)로 보이고, 화면에 "GP 지급됨 · 수령 기록 전"을 띄운다 |
| B | GP가 지급을 기록하면 **자동으로 수령**으로 만든다 (수령일 = GP 지급일). 손이 덜 가지만 우리 장부가 GP 기록을 그대로 따라가 대사의 의미가 줄어든다 |

### Q2. 성과 기준일의 평가액(NAV)

평가액은 분기 보고에서 온다. 예를 들어 6/30 보고 평가액이 100억이고, 그 뒤 9월에 10억을 납입했다면 오늘 기준 평가액은 110억에 가깝다.

| 선택지 | 내용 |
|---|---|
| **A (추천)** | **조정 평가액** = 최근 보고 평가액 + 보고 기준일 뒤 납입 − 보고 기준일 뒤 분배 (업계에서 흔한 단순 롤포워드). 화면에 "6/30 보고 기준, 이후 현금흐름 반영"을 표시 ⚠️ |
| B | 04 그대로: 최근 보고 평가액을 그대로 쓴다 (보고 뒤 납입이 있으면 TVPI·IRR이 낮게 나온다) |

### Q3. 원금 반환 · 수익 구분

GP 분배 단계는 원금 반환 · 기준수익 · 초과수익 · 성과보수 4가지다. 우리 표는 원금 반환 / 수익 두 칸이다.

| 선택지 | 내용 |
|---|---|
| **A (추천)** | 원금 반환 = GP 원금 반환 단계, 수익 = 나머지 단계 합. **단계별 금액은 `gp_components` 에 그대로** 두고 화면에서 펼쳐 보인다 |
| B | 단계별 칸을 따로 만든다 (마이그레이션). 수기 분배도 4단계로 입력 |

### Q4. 성과 · 포트폴리오 화면 형태

| 선택지 | 내용 |
|---|---|
| **A (추천)** | R6는 **표**로 (합계 카드 + 묶음별 표 + 출자 건별 표). 차트는 R7 대시보드에서 한 번에 |
| B | R6에서 차트까지 (묶음별 TVPI 막대, 현금흐름 J커브) |

### Q5. R6 시연용 데모 데이터

지금 데모에는 수령 대기 분배도, 청산된 조합도 없다.

| 선택지 | 내용 |
|---|---|
| **A (추천)** | ① GP 시드에서 'LP연동' 조합에 **2차 분배를 확정만** 해 둔다 (지급 전 → LP "수령 대기", 원금 반환 + 수익 섞인 금액). 면접관이 GP에서 지급 → LP에서 수령 기록 → 대사 일치를 해 볼 수 있다. ② 청산 확인은 **한결(수기)**로 직접 시연 (수기 조합을 청산 완료로 바꾸고 확인). 청산된 연동 조합은 만들지 않는다 (GP에서 회수·최종 분배·청산까지 데이터가 많이 든다) |
| B | ①만 하고 청산 시연 데이터는 두지 않는다 |
| C | ① + GP에 이미 청산된 별도 조합을 하나 만들어 LP에 "청산 확인 가능" 상태로 둔다 (GP 시드 작업이 크다) |
