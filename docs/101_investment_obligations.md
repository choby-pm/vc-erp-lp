# W03 투자 의무 수신·근거 조회 (2026-10-16~17)

## 제품 정책과 구현

사용자 결정(L60): 금액·약정액 비율의 하한/상한, 담당자 수동 인정, 집행 원금 기준·회수 시 자동 차감 없음, 새 규약 적용일 전 거래는 명시적 재판정, 과거 보고 보존. LP에 기업명을 포함한 거래별 인정 근거를 공유하되 투심 메모와 담당자 개인정보는 제외한다. 실제 규약 검증은 W02에서 별도로 진행하며 아직 미확인이다.

공식 [투자 의무 상세](https://guide.lpworks.kr/posts/lfd311/)에서 조건·기간·규약·대상 투자를 연결한 업무 문제를 참고했다. 자동 판정·상한 달성률·모든 투자 원본 공개는 채택하지 않았다.

- 출자 건 상세의 **투자 의무 · 규약과 거래별 인정 근거 확인**에서 진입한다.
- `GET /api/v1/commitments/{id}/obligations?as_of=YYYY-MM-DD` → 세션 기관의 출자 건 검사 → 기관×GP 출자자 연결을 서버가 찾음 → GP 조합원 공개 API 호출 → 허용된 DTO를 Zod로 검증 → 읽기 전용 표시.
- GP의 현재 판정을 조회할 때 받아 표시한다. GP 판정을 LP가 수정하는 쓰기 API는 없다. GP 사본·LP 원장·대사는 변경하지 않는다. 기준일과 실제 응답 수신 시각을 별도로 표시한다.
- 인정 투자 비율과 하한 달성률을 구별한다. 상한은 한도 초과액/잔여액. 적용 기간과 규약 버전·조항·기업명·투자일·인정액·사유·근거 식별자를 제공한다.
- GP 실패/미연동과 의무 0건은 다르다. 실패를 빈 목록으로 숨기지 않는다. 구버전 GP에 endpoint가 없으면 조회 실패로 표시한다.
- 신규 발행 GP 보고의 `snapshot.investment_obligations`는 기존 보고 수신 경로로 보존된다. 보고 화면은 발행 당시 근거를 표시한다. 구 보고의 해당 키가 없으면 소급 생성하지 않고 없다고 안내한다.

관련 코드: `lib/services/obligations.ts`, `lib/schemas/obligations.ts`, `components/investment-obligations.tsx`, 신규 API/화면, 기존 출자·보고 화면. GP 설계는 [상대 저장소 문서](https://github.com/choby-pm/vc-erp-gp/blob/main/docs/101_investment_obligations.md)(로컬 커밋 후 원격 반영 전).

## 검증

로컬 GP3000/LP3200, 하늘연금 관리자, 가상 규약 의무 2개(기간 2025~2028·2025~2027). 동일 코드브릿지 거래에 각각 6억 인정. 약정 150억·하한20% → 인정 비율4%, 하한 기준30억·달성률20%. 상한5억 → 초과1억. 실제 규약으로 표시하지 않았다.

- `scripts/qa-obligations.mjs`: 원금 초과422, 오래된 판정409, 복수 의무, GP/LP 동일 JSON, 내부/개인정보 제외, 바다 기관의 하늘 출자 URL404, 잘못된 날짜400. [기계 결과](qa-reports/2026-10-16-w03-api.json).
- Chrome GP에서 **인정 취소** 폼 제출 → LP 새로 조회에서 인정0원/상한 이내/같은 취소 사유 → GP **재인정** 폼 제출 → LP 인정6억/초과1억 확인.
- [LP 최종 화면](qa-reports/evidence/2026-10-16/w03-lp.jpg), [취소 수신](qa-reports/evidence/2026-10-16/w03-lp-cancelled.jpg).
- GP 독립 회귀 스크립트 27건: 기간 전·중·후, 비율 경계, 버전·재판정·이력, DB 저장 보고 스냅샷 보존, 타 조합/금액 차단, 실제 HTTP 조회권한 POST403 및 비로그인401. 테스트 정의·판정·보고는 롤백, 조회 제한 세션은 폐기.
- GP·LP lint·TypeScript·build 통과. QA 중 JSONB의 키 순서 문자열 비교를 구조 비교로 수정했고 이후 통과했다. 초기 가상 데이터의 불필요한 재판정 표시는 실제 날짜로 정규화해 새 판정으로 바로잡았다.

실행: `node --env-file=.env.local scripts/qa-obligations.mjs`. `--prepare-demo`는 로컬 URL에서만 가상 의무/판정 데이터 준비. 공개 데모에는 실행하지 않는다.

한계: 새 보고 발행→웹훅→LP 수신 전체를 별도 실행한 결과는 아니다. 고정 근거 생성·저장 보존 검증과 기존 수신 코드 검토를 구분한다. 투자 원본 거래 정정/취소 자체는 기존 GP 기능 범위대로이며 이번에는 의무 인정 취소·정정 이력을 추가했다. 현재 조회는 현재 판정으로 과거 거래일 집계이며 과거 당시 조회 상태를 재현하지 않는다.

## 이관·호환·복구

LP 마이그레이션 없음. 기존 보고/원장/단일 주목적 지표를 수정하지 않는다. GP 개발 DB에만 020·021이 적용됐다. 배포할 때 GP DB→GP 코드→LP 코드 순서가 필요하다. 구 보고 JSON에 새 근거를 만들지 않는다. 복구 시 LP 코드를 되돌리면 기존 업무는 그대로이며 GP 의무 감사 테이블은 보존한다. 로컬 QA용 가상 의무와 판정 이력만 추가했고 공개 데모 갱신은 하지 않았다.

AI는 코드·검증·문서 작성, 사용자에게서 확인한 제품 정책만 확정했다. 사용자가 기능별 커밋을 요청했고 푸시·배포는 요청하지 않았다.
