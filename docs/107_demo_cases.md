# GP·LP 세 가지 데모 케이스

GP와 LP 로그인 화면에서 같은 이름의 버튼을 선택한다. 비밀번호를 전달하지 않고 데모 버튼으로 로그인한다. 케이스의 업무 담당과 승인 담당은 서로 다른 계정이다.

| 버튼 | GP 시작 상태 | LP 시작 상태 | 목적 |
|---|---|---|---|
| 처음부터 체험 | 출자자 연결과 계정만 준비. 새 조합 입력부터 시작 | 운용사 연결과 계정만 준비. 예산·제안·출자 건 없음 | 전체 흐름 직접 진행 |
| 완료 결과 확인 | 투자 승인·집행·회수·보고·최종 분배·청산 완료 | 심사·선정 결재·결성·납입·분배 수령·청산 확인 완료 | 처리 결과와 근거 확인 |
| 이어서 체험 | 결성·등록·최초 납입 완료. 투자 지시 미승인, 추가 콜 발송, 보고 초안 | 선정·결성 완료. 최초 납입 기록, 추가 콜 미납·납입 결재 대기 | 남은 단계 직접 진행 |

기존 하늘연금·바다성장출자 및 기존 조합 데이터는 유지한다. 새 LP 기관 세 곳의 데이터는 서로 분리된다. GP는 한 운용사의 공용 공간이므로 케이스별 계정도 다른 조합을 조회할 수 있다. GP 케이스 구분은 접근 권한 경계가 아니다.

## 계정과 역할

| 서비스 | 로그인 화면 역할 | 할 일 |
|---|---|---|
| GP | 업무 담당 | 제안·조합·납입·투자 지시·보고·분배 처리 |
| GP | 승인 담당 | 다른 계정이 기안한 투자 실행 지시 승인 |
| LP | 출자 담당 | 심사·선정 및 납입 기안·투표·수령 기록 |
| LP | 결재권자 | 다른 계정이 올린 선정·납입·투표 결재 |
| LP | 관리자 | 전체 업무와 사용자·연동 상태 확인 |

역할 변경은 로그아웃한 뒤 같은 케이스를 다른 역할로 다시 선택한다. 같은 브라우저 프로필의 탭은 로그인 쿠키를 공유하므로, 여러 탭을 열었다고 서로 다른 역할이 유지되지는 않는다. GP와 LP는 별도 사이트이므로 각각 로그인할 수 있다.

## 1. 처음부터 체험

1. LP에서 예산 20억 원과 초기 분야 배분을 만든다. 기본 심사 항목의 가중치 합계를 확인한다.
2. GP에서 새 벤처투자조합을 만들고 규약·대표펀드매니저를 등록한 뒤 모집을 시작한다. 최소 결성액과 GP 출자 요건은 화면의 점검표를 따른다.
3. GP에서 **체험 1 · 처음부터 체험 출자기관**에 출자 제안을 발송한다. LP에서 ‘지금 가져오기’ 후 제안이 접수됐는지 확인한다.
4. LP 출자 담당으로 심사 단계와 평가표를 작성하고 선정 조건을 저장해 결재를 올린다. 결재권자로 전환해 승인한다. GP에서 확약과 선정 조건 수신을 확인한다.
5. GP에서 조합원 명부·최초 콜·결성총회·등록·필수 기관을 처리한다. LP에서 결성 확인 점검표를 완료한다. 실제 결성액과 약정이 선정 조건을 충족해야 한다.
6. 아래 ‘이어서 체험’의 납입·투자·보고·투표·분배·청산 흐름을 이어간다. 새 조합은 기존 케이스 2·3 조합과 다른 이름을 사용한다.

## 2. 완료 결과 확인

GP 조합 **체험 2 · 완료 결과 확인 조합**과 LP의 같은 이름 출자 건을 연다.

- GP: LP 약정 19억 원 + GP 약정 1억 원, 최초 납입 총 200만 원, 투자 10만 원, 회수 12만 원, 최종 분배 후 현금 0원, 청산 완료를 확인한다.
- 투자 실행 지시의 기안자와 승인자가 다르며, 실제 집행에 연결된 승인 조건을 확인한다.
- 결성·해산 총회 안건과 결과, 보고 발행본, 최종 분배의 조합원별 배분 및 장부를 확인한다.
- LP: 심사 이력, 85점 평가표, 선정 조건과 승인 결재, 최초 납입 190만 원, 분배 수령, 대사 결과, 청산 시 고정된 최종 성과를 확인한다.
- 보고서는 2026년 3분기 말 기준의 스냅샷이다. 그 이후 발생한 투자·회수와 현재 장부의 금액이 다를 수 있다. 기준일을 맞춰 비교한다.

이 기록은 체험용 가상 과거 데이터다. 생성 스크립트 실행이나 완료 상태가 모든 기능의 브라우저 QA 통과를 의미하지는 않는다. 반려·취소·철회·공유 회수 등 예외 분기는 별도로 실행해야 한다.

## 3. 이어서 체험

GP 조합 **체험 3 · 이어서 체험 조합**과 LP의 같은 이름 출자 건을 연다.

1. LP 추가 콜의 우리 몫 **19,000원**으로 준비된 납입 기안을 확인한다. 본인 결재가 차단되는지 확인한 뒤 결재권자로 승인한다. 출자 담당으로 가상 송금 완료를 기록한다. 새 기안부터 시험하려면 기존 기안을 취소한 뒤 다시 작성한다.
2. GP에서 같은 콜에 해당 LP의 납입 19,000원을 기록하고 LP에서 다시 맞춘다. 금액·회차·날짜와 납입 대사가 일치하는지 확인한다. GP 자신의 몫 1,000원도 기록해야 콜 전체가 완납된다.
3. GP 업무 담당으로 준비된 투자 지시 100,000원을 확인한다. 본인 승인은 차단되어야 한다. 승인 담당으로 승인한 뒤 업무 담당으로 집행한다. 조건을 변경하면 기존 승인을 재사용하지 못하는지도 별도 기안으로 시험한다.
4. GP 보고 초안을 확인하고 공개 범위를 허용한 뒤 발행한다. LP에서 보고 수신·검토와 기준일 성과를 확인한다. 자료 요청·추가 회신은 LP 출자 건의 자료 요청에서 별도로 시작한다.
5. 총회를 소집하고 LP 출자 담당으로 투표를 기안한다. 결재권자 승인 후 GP 수신·총회 결과를 확인한다. 과거 결성총회는 이미 끝났으므로 새 총회를 사용한다.
6. 투자 회수와 일반 분배를 처리한다. LP 수령 기록과 GP 지급 장부의 대사를 확인한다. 분배 전에는 지급일과 현금 잔액 조건을 확인한다.
7. 보유 자산을 모두 회수하고 해산총회·해산·최종 분배·청산을 순서대로 처리한다. LP는 미납·미수령·대사 불일치가 없어야 청산 확인할 수 있다.

공유 차단·취소·철회·결산 잠금처럼 이후 단계에 영향을 주는 시험은 마지막에 한다. 실제 개인정보·계좌·비밀값은 입력하거나 첨부하지 않는다. 모든 금전 기록은 가상 데이터이며 실제 송금 기능은 없다.

## 사람 또는 AI에게 전달할 실행 지시

> GP와 LP에서 같은 케이스를 선택하고 위 순서대로 화면에서 업무를 진행하세요. 각 단계의 계정·기준일·입력·기대 결과·실제 결과와 화면 증거를 남기세요. 다른 케이스의 기록을 변경하지 마세요. API 검증과 브라우저 검증을 구분하고, 판정은 ‘확인 완료 / 기록만 확인 / 미완료·불일치’로 남기세요. 실행하지 못한 기능은 이유를 적고, 업무 결과를 바꾸는 정책은 임의로 정하지 말고 질문으로 남기세요. 비밀번호·키는 출력하거나 업로드하지 마세요. 매일 03:00~04:00 KST에는 배포 데모를 조작하지 마세요.

## 운영자 복원

데모 원본에 시작 상태를 보존한다. 테스트 종료 후 운영자가 LP 폴더에서 `node scripts/demo-restore.mjs`를 실행하면 GP와 LP가 원본으로 돌아간다. `npm run db:demo-refresh`는 사용하지 않는다. 복원은 다른 방문자의 진행도 되돌리므로 동시에 테스트하지 않는다.

원본 생성은 `gp/scripts/seed-demo-cases.mjs` → `lp/scripts/seed-demo-cases.mjs` 순서다. 두 스크립트 모두 Neon에서 확인한 demo-seed 주소와 `REVIEW_DEMO_BRANCH_ID`, 개발 모드, 운영자가 지정한 비공개 임시 `REVIEW_CASE_EXPORT` 경로가 필요하다. GP 스냅샷은 LP 원본 구성에만 사용하며, 실제 연동 QA와 구분한다. 기존 비밀번호와 연동 키는 교체하지 않는다.
