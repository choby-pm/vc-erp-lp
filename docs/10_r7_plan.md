## 1. R7에서 보여줄 것

R7은 **마지막 릴리스**다. 새 업무 기능은 더하지 않고, 지금까지 만든 것을 **한 화면에서 보이게** 하고, **처음 보는 사람이 끝까지 따라가 볼 수 있게** 정리한다.

```
대시보드        올해 예산 사용 · 포트폴리오 합계 · 30일 일정 · 차트 · 주의 목록 (한 화면)
숫자 일치       대시보드 = 성과 화면 = 출자 건 상세 = 예산 화면 (성공 기준 6)
데모 데이터     성공 기준 1~7을 데모 기관으로 끝까지 볼 수 있게 (완료된 이력 + 직접 해볼 거리)
제출용 요약     GP의 00_summary 처럼 한 장 요약 + 둘러보기 순서 + 단순화(⚠️) 목록
```

## 3. 단계별 계획 (5단계, 순서대로)

각 단계가 끝날 때마다 검수 요청을 드린다.

### R7-1. 대시보드 숫자 · 30일 일정

| 할 일 | 내용 |
|---|---|
| 예산 사용 | 올해 예산 총액 · 사용(선정 + 선정 결재 대기, BR-BUD-03) · 잔액, 분야별 배분 대비 사용 (예산 화면과 같은 함수). 약정·납입은 포트폴리오 카드에 |
| 포트폴리오 합계 | 성과 화면 합계를 그대로 (TVPI · DPI · RVPI · 합산 IRR, 출자 건 수, 평가액 없음 경고) |
| 30일 일정 | 오늘부터 30일: 캐피탈콜 납입 기한 · 총회 투표 마감 · 분배일 · 결성 기한 · 출자사업 접수 마감 · 보고 제출 기한. 날짜순, 누르면 해당 화면 |
| API | `GET /dashboard` 에 `budget` · `portfolio` · `schedule` 를 더한다 (주의 목록은 그대로) |

> R7-1 구현 (2026-10-04): `lib/services/dashboard.ts` (getDashboard · getSchedule), `GET /dashboard` 확장, 대시보드 화면(숫자 카드 3개 → 주의 목록 → 30일 일정). DB 변경 없음
> 검수: 하늘 예산 70억/500억(예산 화면과 같음), 포트폴리오 TVPI 1.125·IRR 14.5%(성과 화면과 같음), 10월 납입 예정 26.56억(확정 25억 + 추정 1.56억, 자금 계획과 같음), 30일 일정 5건(한결 1회 콜·2차 분배·정기총회·출자사업 마감·4회 콜). 바다: 예산 없음, 기한 지난 미납 4억(3회 콜). 보고 기한은 주의 목록과 같은 규칙(L35) — 2027-01-20 기준으로 4분기 보고 기한 2027-02-14 두 건 확인

## 4. 정할 것

### Q1. 차트를 어떻게 그릴까?

| 선택지 | 내용 |
|---|---|
| **A (추천)** | **직접 그린다** (SVG·막대 몇 개). 차트 3개가 모두 단순 막대라 라이브러리 없이 충분하다. 의존성이 늘지 않고 화면이 가볍다. 마우스 올리면 금액 표시 정도까지 |
| B | 차트 라이브러리(Recharts 등)를 넣는다. 모양·애니메이션이 좋지만 의존성과 화면 무게가 늘고, 서버에서 그리는 지금 구조와 맞추는 작업이 생긴다 |

### Q2. 대시보드 배치

| 선택지 | 내용 |
|---|---|
| **A (추천)** | 위에서부터 **숫자 카드**(예산 사용 · 포트폴리오 TVPI·IRR · 이번 달 납입 예정) → **주의 목록**(할 일) → **30일 일정** → **차트 3개**. 처음 보는 사람이 "규모 → 할 일 → 다가오는 일 → 추세" 순으로 읽는다 |
| B | 주의 목록을 맨 위에 두고 숫자·차트는 아래로. 매일 쓰는 담당자에겐 편하지만, 데모로 처음 볼 때는 전체 그림이 늦게 보인다 |

### Q3. 데모 데이터를 어떻게 만들까?

| 선택지 | 내용 |
|---|---|
| **A (추천)** | **시나리오 스크립트**(`scripts/seed-scenario.mjs`)로 만든다. GP 시드처럼 서비스 함수를 불러 규칙 검사를 그대로 거치고, **이미 있으면 건너뛴다**(지금 데이터 위에 더함, 여러 번 돌려도 같음). 날짜는 과거 이력으로 고정. 다시 만들 수 있고 무엇을 넣었는지 코드로 남는다 |
| B | 개발 DB에 화면·API로 직접 더한다. 빠르지만 다시 만들 수 없고, 무엇을 넣었는지 기록이 흩어진다 |
| C | 데이터를 비우고 스크립트로 처음부터 다시 만든다. 가장 깔끔하지만 GP 연동 연결·가져온 출자 건까지 다시 만들어야 해 위험이 크다 |

### Q4. 데모에 "직접 해볼 거리"를 남길까?

| 선택지 | 내용 |
|---|---|
| **A (추천)** | **완료된 이력 + 직접 해볼 거리 둘 다.** 상반기 출자사업은 선정까지 끝난 이력으로, 연동 딥테크 제안·4차 콜 납입·정기총회 투표·2차 분배 수령·Q2 보고 검토·한결 청산은 **누르기 전 상태**로 둔다. 데모는 매일 03:00 초기화되니 여러 사람이 해 봐도 다음 날 원래대로 |
| B | 전부 완료된 상태로 둔다. 숫자는 꽉 차 보이지만, 연동(LP에서 선정 → GP에서 확약)을 직접 눌러 볼 수 없다 |

### Q5. 상반기 출자사업의 수기 GP 3곳

| 선택지 | 내용 |
|---|---|
| **A (추천)** | 수기 운용사 3곳(한결벤처스 + 가상 2곳)이 상반기 출자사업에 제안 → 심사 평가 → 2곳 선정(한결 포함, 이미 있는 한결 출자 건과 이어짐) · 1곳 탈락. 연동 GP(VC ERP 데모 운용사)는 개별 제안형(딥테크)으로 "직접 해볼 거리"에 둔다. 이름은 모두 가상 |
| B | 연동 GP도 상반기 출자사업에 넣는다. GP 시드도 함께 바꿔야 해서 GP 저장소 변경이 생긴다 |
