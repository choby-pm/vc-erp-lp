# 96. QA 시나리오 — GP · LP 업무 흐름 순서

> GP(운용사)와 LP(출자기관)가 실제로 일하는 순서대로, 각 단계에서 **한쪽이 한 일이 다른 쪽에 제대로 도착하는지**까지 확인한다.
> 실행 스크립트: `npm run qa:e2e` (`scripts/qa-e2e.mjs`), 결과지: `npm run qa:report` → `docs/qa-reports/<날짜>.md · .csv`. 배포 GP·LP 사이트에 실제로 요청을 보내고, 끝나면 짝 맞춘 데모 갱신으로 처음 상태로 되돌린다.
>
> - 환경: 배포 LP <https://vc-erp-lp.vercel.app> ↔ 배포 GP <https://vc-erp-gp.vercel.app> (웹훅·응답 API가 실제로 오가는 유일한 환경)
> - 시작 상태: 데모 시드 그대로 (매일 03:00 초기화 상태). 하늘연금 = 시나리오 주인공, 바다성장출자 = 기관 분리 확인용
> - 표기: 🔗 = GP와 LP 사이를 오가는 확인, ⛔ = 막혀야 하는 것을 막는지
> - 결과 기록: 아래 표 오른쪽 "결과"는 마지막 실행 결과 (실행 기록은 맨 아래)

## 흐름 한눈에

```
LP  1 계획 · 출자사업 공고 ────────🔗──→ 공고 게시판 (모든 기관 · 연동 GP)
GP  2 출자 제안 발송 / 공고에 지원 ─🔗──→ LP 제안 자동 접수 (공고 지원은 그 부문에)
LP  3 심사 · 선정 결재 ──────────🔗──→ GP 출자 제안 "확약 · LP 직접" + 선정 조건(앵커 조건)
GP  4 결성  ·  LP 결성 확인 (수기 조합은 LP가 입력)
GP  5 캐피탈콜 발송 ──────────────🔗──→ LP 콜 수신 → 납입 결재 → 송금
GP    입금 확인 ──────────────────🔗──→ LP 납입 대사 "일치"
GP  6 공지 · 보고 · 총회 ─────────🔗──→ LP 통지함 · 보고 검토 · 투표 결재
LP    받음 확인 · 투표 ──────────────🔗──→ GP 확인 표시 · "LP 직접" 투표
GP  7 분배 확정 · 지급 ─────────────🔗──→ LP 수령 대기 → 수령 기록 → 분배 대사 "일치"
LP  8 성과 · 대시보드 (숫자 일치)
GP  9 청산  ·  LP 청산 확인 → 최종 성과 고정
공통 10 기관 분리 · 웹훅 위조 · 놓친 이벤트 · 화면
```
