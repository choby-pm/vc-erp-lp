# 97. 시연 대본 (약 17분)

> 배포 사이트에서 GP·LP 두 시스템을 보여줄 때 화면별로 할 말. 순서는 [00 제출용 요약](00_summary.md) 5장 둘러보기와 같고, 캡처가 들어간 소개 페이지는 <https://vc-erp-lp.vercel.app/intro> 이다.
>
> - LP <https://vc-erp-lp.vercel.app> · GP <https://vc-erp-gp.vercel.app> — 첫 화면 "데모로 둘러보기"
> - 데모는 매일 03:00(KST)에 처음 상태로 돌아간다. 시연 전에 누가 먼저 눌렀다면 2·3·4·6번 화면이 이미 바뀌어 있을 수 있다
> - 브라우저 창 두 개를 띄워 둔다: 왼쪽 LP(하늘연금 · 출자 담당), 오른쪽 GP(관리자)

---

## 시작 (1분)

> "VC 운용사가 조합을 운용하는 GP 시스템과, 그 조합에 출자한 기관이 쓰는 LP 시스템을 따로 만들고 연동했습니다. GP는 원본을 만들고, LP는 그 숫자를 받아 우리 돈이 제대로 나가고 들어왔는지 확인하고 여러 조합의 성과를 모아 봅니다. LP의 핵심은 계산보다 결정(심사·결재), 확인(대사), 모아 보기(분석)라고 봤습니다."

## 0. 대시보드 (1분) — LP · 출자 담당

- 위 카드: 올해 예산 170억/500억 · 포트폴리오 TVPI 1.13배 · IRR 14.5% · 이번 달 납입 예정
- 아래: 주의 목록(결성 기한 임박 · 수령 대기 분배 · 투표할 총회 · 검토 안 한 보고), 30일 일정, 차트 3개

> "이 숫자는 저장하지 않습니다. 예산·성과·자금 계획 화면과 같은 함수로 계산해서 화면끼리 어긋날 수 없고, 점검 스크립트로 85개 항목을 비교합니다."

## 1. 예산 → 공고 → 심사 → 선정 (2분) — 출자 심사

- 출자사업 "2026년 정기 출자사업" → 초기 부문 200억, 접수 3건 · 선정 2곳
- "미래로 씨앗 2호" 상세 → 선정 결재 점검표의 ✕ "모집 부문 출자 예정액", 단계 이력의 탈락 사유

> "한결과 새솔이 선정돼 170억을 썼고, 미래로는 50억을 요청했는데 부문에 30억밖에 남지 않아 선정 결재가 올라가지 않았습니다. 예산 잔액·부문 한도는 막고, 분야 배분 초과는 실무에서 전용이 흔해 경고만 합니다. 점수로 자동 선정하지 않는 것도 같은 이유입니다."

## 2. 공고 게시판 → GP 지원 → 앵커 조건 (2분) — 출자 심사 → GP 화면

- LP: 출자 심사 → **공고 게시판** — 하늘연금 · 바다성장출자 두 기관의 접수 중 공고 (다른 기관 공고는 공고 항목만)
- GP: **출자사업 공고** → 바다 "2026년 하반기 성장 출자사업" → 그로스 1호(성장 · 기획 중) · 성장 부문 · 40억 → **이 조합으로 지원**
- LP 바다: 출자사업 화면 "접수된 제안"에 **GP 연동 지원** → 서류 심사 · 평가 · 선정 조건(40억 · 상한 30% · 결성 기한) → 결재 → 승인
- GP: 그로스 1호 → 출자 제안 → **앵커 조건**: 필요한 최소 결성액 200억(최소 결성 규모) · 남은 모집액 160억 · D-day

> "정책 출자기관은 공고를 올리고 GP가 찾아와 지원합니다. 이 서비스를 쓰는 기관들의 공고가 한 게시판에 모이고, 연동된 GP는 GP ERP에서 바로 지원합니다. 조합 분야가 부문 분야와 다르면 막습니다. 접수 기간은 LP가 받은 순간으로 보고, 선정되면 결성 기한 · 비율 상한이 GP로 가서 '얼마를 더 모아야 결성할 수 있는지'가 바로 보입니다. 나머지 출자금은 지금처럼 다른 LP에게 개별 제안으로 모읍니다."

(시간이 있으면: 성장 조합으로 하늘 "초기 부문"에 지원하면 분야가 달라 막힌다는 것)

## 3. LP 선정 → GP 확약 (2분) — 출자 심사 → GP 화면

- 출자 제안 "딥테크 스케일업"(연동) → **선정 결재 올리기**
- 결재권자로 바꿔 결재함 → **승인**
- GP: 딥테크 조합 → 출자자·조합원 → 출자 제안 → 하늘연금 **확약 · LP 직접**

> "이 제안은 GP에서 발송하자 웹훅으로 자동 접수된 것입니다. 승인하는 순간 LP가 GP의 응답 API를 불러 확약이 생기고, GP 담당자가 대신 입력한 것과 구분되게 'LP 직접'이 붙습니다."

## 4. 캐피탈콜 → 납입 → 대사 (3분) — 납입·분배

- 캐피탈콜 "LP연동 · 4회" → **납입 기안** → 결재권자 승인 → **송금 완료 기록**
- 출자 건 상세 → 장부: 납입 우리 35억 / GP 30억 **불일치 · 확인 대기**
- GP: LP연동 조합 → 캐피탈콜 4회 → 하늘연금 **입금 기록**
- LP 새로고침 → 납입 **일치**, 대사 이력에 불일치 → 일치

> "우리 장부와 GP 원장 사본을 따로 두고 비교합니다. 송금일과 GP 입금 확인일이 다른 건 정상이라 7일은 확인 대기로만 둡니다. 웹훅은 신호로만 쓰고 받으면 GP API를 다시 읽기 때문에, 하나를 놓쳐도 다음 동기화가 맞춥니다. 장부와 대사 이력은 추가만 되고, 틀리면 취소 행으로 정정합니다."

(시간이 있으면: 금액을 일부러 다르게 송금 기록하면 7일 뒤 주의 목록에 올라간다는 점)

## 5. 총회 투표 (2분) — 사후관리 → GP 화면

- 총회 "LP연동 · 정기총회" → 안건마다 찬반 · 검토 의견 → **투표 결재 요청** → 결재권자 승인
- GP: LP연동 조합 → 총회·보고 → 정기총회 → 하늘연금 줄 **LP 직접 · 찬성**

> "결재가 승인된 투표안과 지금 투표안이 같을 때만 제출합니다. 승인 뒤에 누가 찬반을 바꾸면 제출되지 않습니다. GP는 LP가 직접 넣은 표를 바꿀 수 없습니다."

## 6. 포트폴리오 성과 (1분) — 포트폴리오 → 성과

- 합계 카드, 빈티지 · 분야 · 운용사 · 연동/수기 모아 보기, 출자 건별 표
- 출자 건을 눌러 기준일을 바꿔 보고, 현금흐름(IRR 근거)을 펼침

> "배수는 평균하지 않고 금액 합계로 다시 나누고, IRR은 모든 현금흐름을 합쳐 한 번 계산합니다. 엑셀 XIRR 예시값과 같게 나오는지 검증했습니다. 평가액은 최근 보고에 그 뒤 납입을 더하고 분배를 뺀 값이라 화면에 단순화라고 밝혀 두었습니다."

## 7. 청산 (2분) — 조합·운용사 → 포트폴리오

- 조합 "한결 초기 1호" → 상태를 **청산 완료**로
- 출자 건 상세 → 청산 조건표: 미완납 캐피탈콜 ✕
- 1회 콜 납입(기안 → 승인 → 송금) → 조건 모두 ✓ → **청산 확인**
- 최종 성과 고정 카드, 대시보드 숫자가 성과 화면과 같은지

> "미납 콜, 수령 대기 분배, 확인 안 한 대사 불일치가 하나라도 있으면 청산할 수 없습니다. 확인하면 청산일 기준 성과가 고정되고 이후 기록은 막힙니다. 이 단계를 검수하다 TVPI가 넷째 자리에서 0.0001 어긋나는 걸 점검 스크립트가 찾아서 고쳤습니다."

## 8. 기관 분리 (1분)

- 로그아웃 → **바다성장출자**로 로그인

> "같은 GP 조합에 두 기관 모두 출자했지만 각자 자기 몫만 봅니다. 모든 표에 기관 ID가 있고, 기관을 건너는 연결은 DB의 복합 외래 키가 막습니다. 하늘연금 주소를 직접 열면 404가 납니다."

## 마무리 (30초)

> "실무 규칙을 확인하지 못한 부분은 단순화하고 화면과 문서에 밝혔습니다. GP 31개, LP 30개를 실무 확인 목록으로 모아 두었고, 다음은 여러 단계 결재선과 전결 규정입니다."

## 예상 질문

| 질문 | 답 |
|---|---|
| 웹훅이 안 오면? | 웹훅은 신호일 뿐이라 하루 1회 주기 작업과 관리자 "지금 가져오기"가 놓친 이벤트를 가져온다. 처리 실패는 5번까지 다시 하고 관리자 주의 목록에 띄운다 |
| GP 숫자를 그대로 쓰지 않는 이유는? | LP는 자기 돈이 실제로 나가고 들어왔는지 확인해야 한다. 우리 장부(송금·수령 기록)와 GP 원장 사본을 나눠 두고 비교하는 것이 대사다 |
| 두 번 눌러 납입이 두 번 기록되지 않나? | 돈이 걸린 요청은 Idempotency-Key로 한 번만 처리한다. 결재 승인 순간에는 예산 행을 잠그고 다시 검사한다 |
| 다른 GP 조합은? | 연동되지 않은 GP의 조합은 담당자가 직접 입력한다(수기). 성과·자금 계획·청산은 똑같이 계산한다. 대사는 연동 조합만 |
| 다른 LP도 공고를 보고 참여하나? | 공고는 기관이 GP를 뽑는 절차다. 다른 LP는 공고에 지원하지 않고, 선정된 GP가 개별 제안으로 모은다 ⚠️. 다른 LP에게 더 쓸모 있는 "누가 선정됐는지" 공개는 고도화 |
| 왜 결재자가 한 명인가? | MVP 범위로 정했다(L4). 여러 단계 결재선과 금액별 전결 규정은 다음 단계 |
