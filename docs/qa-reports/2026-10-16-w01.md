# W01 기준일 오류 수정·검증 (2026-10-16)

## 범위와 결정

요구사항: `portfolio/next-work-instructions.md` W01 → BR-PERF-01·02 → L58 → `lib/performance-date.ts`, 상세/전체 화면, 두 성과 API.
사용자가 이 세션에서 선택: 잘못된 날짜는 오류 안내·계산 중단, 미래 날짜 허용. 미입력·빈 값은 기존 화면처럼 KST 오늘.
정상 과거 날짜가 오늘로 대체되던 정규식 오류를 공통 검증 함수로 교체했다. `Date.parse`가 2월 30일을 3월로 보정하는 것도 왕복 검증으로 막는다. 상세의 현재 업무 상태와 기준일 누적 성과를 별도로 설명한다.

- 상세·전체에 `?as_of=2026-02-30` 직접 접근: 오류 안내, 성과 계산 미표시.
- 상세 기준일 생략·빈 날짜 폼 제출: `2026-10-16` 기본값 표시.
- 전체 성과 `2099-12-31`: 날짜 유지·조회 가능. 미래 거래 예측값은 아니며 현재 기록된 흐름만 계산한다.
- 날짜 단위 회귀 13건 통과: 윤년·평년·형식·중복 값·빈 값·미래.
- 개발 DB 읽기 검증 27개 기준일: 원장 행 독립 합산과 상세/포트폴리오의 약정·납입·분배·NAV·배수·IRR 일치.
- 롤백 트랜잭션 임시 데이터: 납입 100,000,001원(2090-01-10), 분배 40,000,001원(1/20), 납입 취소 -100,000,001원 및 재기록 90,000,001원(1/30). 각 사건 전날/당일/다음날 9건의 순액·현금흐름 확인. 롤백 뒤 임시 행 0건 확인. 정정은 브라우저 실행으로 주장하지 않는다.
- 검증 스크립트 첫 실행은 테스트 기대값의 `-0` 엄격 비교로 실패했다. 금액 0의 기대값 표현을 수정한 뒤 재실행 통과. 제품 계산 오류가 아니다.
- `npm.cmd run lint`, `npx.cmd tsc --noEmit`, `npm.cmd run build` 통과. 최초 sandbox 빌드는 Google Fonts 연결 제한으로 실패, 네트워크 허용 후 정상 빌드.

재실행: `node scripts/check-performance-dates.mjs`; DB 포함: `node --env-file=.env.local scripts/check-performance-dates.mjs --db`.

## 데이터·호환·복구

스키마 변경·기존 데이터 재계산·원장 덮어쓰기 없음. UI/JSON API의 잘못된 날짜 처리만 L58로 명시했다. API의 빈 값은 화면과 동일하게 오늘을 사용한다. 새로운 마이그레이션 없음. 코드 변경을 되돌리면 복구되며 DB 복구는 필요 없다. 테스트 로그인은 개발 DB 세션/감사 기록을 생성한다. 공개 데모 데이터에는 쓰지 않았다.

잔여 한계: 과거 조회는 현재 저장된 정정·보고 대체 상태를 날짜로 집계한다. 당시 조회자가 보았던 모든 상태의 시간여행 조회가 아니다. 청산된 건의 NAV 0 처리 등 기존 BR-PERF-02는 유지했다. 공개 배포 브라우저 재검증은 배포 이후 필요하다.
