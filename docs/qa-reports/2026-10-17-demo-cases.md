# 2026-10-17 GP·LP 데모 3개 케이스 검증

## 결과

GP와 LP 로그인 화면에 모두 `처음부터 체험`, `완료 결과 확인`, `이어서 체험` 버튼 3개가 표시된다. 배포된 최신 화면에서 각 버튼으로 로그인해 해당 데이터 상태에 도달하는 것을 브라우저로 확인했다.

| 케이스 | GP 화면에서 확인 | LP 화면에서 확인 |
|---|---|---|
| 처음부터 체험 | 새 조합 기획 화면으로 이동 | 출자 건·예산이 없는 기관 대시보드 |
| 완료 결과 확인 | 청산 완료 조합, 투자·회수·보고·분배 기록 | 닫힌 출자 건, TVPI 1.01x, IRR 2.5%, 최종 분배 내역 |
| 이어서 체험 | 운용 중 조합, 미납 캐피탈콜과 보고 초안 | 활성 출자 건, 납입 결재 대기와 후속 업무 |

GP는 케이스별 데모 사용자를 제공하지만 하나의 운용사 작업공간을 공유한다. LP는 케이스별 기관과 권한 범위를 분리한다.

## 검증

- 배포 브라우저 QA: GP 3/3, LP 3/3 케이스 버튼 로그인 및 목적 화면 확인.
- 배포 API QA: GP·LP 계정, 시작 상태, 권한 차단, 잘못된 케이스·역할 거절 등 53/53 통과. API QA 결과를 브라우저 QA로 계산하지 않았다.
- GP·LP 연동 회귀 QA: 44/45 통과. 남은 한 항목은 LP QA 스크립트의 하위 프로세스 실행이 로컬 샌드박스에서 `EPERM`으로 차단된 것이다. 같은 배포 DB를 대상으로 숫자 일치 검사를 직접 실행해 204개 검증 항목이 모두 통과했다.
- QA 종료 후 `node scripts/demo-restore.mjs`를 직접 실행해 GP와 LP를 `demo-seed` 원본으로 복원했다. 복원 이후 배포 API QA 53/53을 다시 실행했다.
- 변경 코드의 비밀값 검사: 금지 파일 0개, 비밀값 일치 0건, 키 패턴 0건. GitHub push는 하지 않았다.

## 남은 관찰 사항

이어서 체험의 LP 대시보드에는 납입 승인 대기와 함께 2분기 보고 미제출 알림도 표시된다. 이는 실제 남은 업무지만 GP의 3분기 보고 초안과 기간이 다르므로, 처음 보는 사용자는 어느 보고부터 처리할지 혼동할 수 있다. 데이터상 3분기 보고 초안은 GP에서 작성 후 발행하고 LP에서 수신·검토하는 시나리오다.
