# 과거 배포 계정 파일 후속 보안 조치

2026-10-17 KST 사용자 승인: 계정 파일이 포함된 과거 배포 삭제와 관련 비밀번호 교체. 파일·비밀번호·키 원문은 이 보고서나 실행 출력에 넣지 않았다.

## 범위와 결과

- Vercel LP 배포 15개를 파일명으로 전수 조사했다. 현재 production 배포에는 계정 파일이 없었고 과거 배포 14개에 `demo-accounts.md`가 있었다.
- 과거 파일의 계정 식별자를 메모리에서 대조해 LP 계정 6개를 교체 대상으로 확인했다. GP 계정 파일과 계정이 겹치지 않아 GP 비밀번호·QA GP 승인자 secret은 변경하지 않았다.
- LP main·demo·demo-seed·demo-seed-backup 2개, 총 5개 DB 사본에서 해당 6개 계정의 비밀번호 해시만 교체하고 기존 로그인 세션을 폐기했다. 사용자 역할·기관·업무 원장은 변경하지 않았다. 자동 초기화나 백업 복원으로 과거 비밀번호가 다시 유효해지는 경로를 줄이기 위해 원본·백업에도 적용했다.
- 각 사본에서 새 해시 저장과 과거 배포 파일의 이전 비밀번호 거부를 확인했다. 새 비밀번호는 Git에서 제외된 로컬 `demo-accounts.md`에만 기록했다. 백업·원본 접속에 필요했던 임시 컴퓨트 3개는 제거했다.
- 새 관리자 비밀번호로 로컬·배포 로그인 HTTP 200을 확인하고 각 테스트 세션은 로그아웃 HTTP 200으로 종료했다. 이 검사는 API 검증이며 브라우저 검증으로 세지 않는다.
- 과거 배포 14개를 삭제한 뒤 각 배포 API가 404임을 확인했다. 현재 production 배포 `dpl_D1EBWMnvxduv6jzwqVVLSBL9TewW`와 서비스 별칭은 보존했고 Ready 상태를 확인했다.
- 최종 재조회에서 남은 LP 배포는 현재 1개, 계정 파일 포함 배포는 0개다. 삭제된 배포로는 롤백할 수 없다.

## 증거

- [배포 삭제 결과](2026-10-17-deployment-cleanup.json): 대상 배포 ID·삭제 후 확인 결과를 완료한 목록과 현재 보존 ID.
- [비밀번호 교체 결과](2026-10-17-password-rotation.json): DB 사본별 계정 수·이전 비밀번호 거부·세션 폐기 확인. 비밀번호·해시 없음.
- [새 비밀번호 로그인 확인](2026-10-17-password-login-check.json): 로컬·배포 로그인과 로그아웃 상태 코드. 식별자·비밀번호·쿠키 없음.

공개 유출이나 악용이 있었다고 확인한 것은 아니다. Vercel의 삭제 후 접근 불가를 확인했으며 제공업체 내부 보존 정책이나 Neon의 모든 시점 복원 이력에서 정보가 물리 삭제됐다고 주장하지 않는다. 구 시점으로 DB를 복원한다면 비밀번호 재교체가 필요하다.

새 앱 배포·push·업무 데이터 초기화·`db:demo-refresh`는 하지 않았다. 기존 검수 보고서는 당시 상태의 기록으로 유지한다.
